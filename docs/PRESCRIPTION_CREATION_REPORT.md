## Поддержка и формы

| Тип | Форма и сохранение |
| --- | --- |
| MONITORING | Название, начало, периодичность, инструкция, цвет; без specifics |
| ACTIVITY | Те же поля и «Планируемое». Выключение исключает periodicity из dates, не добавляет выдуманный boolean в specifics |
| PROCEDURE | Базовые поля, отдельный словарь; без specifics |
| NURSING | Базовые поля, отдельный словарь; исправлена прежняя подпись «Процедура» |
| SOLUTION | Базовые поля; масса; дефицит как заданная скорость мл/ч либо дегидратация, доля и длительность восполнения; поддержание; продолжающиеся потери мл/кг/ч; суммарная скорость |
| MEDICATION | Базовые поля; числовая концентрация, отдельно enum вещества и количества препарата; путь; доза и enum вещества, массы/животного, времени; масса расчёта; ИПС; режим отображения; восстановление флакона; дополнительное разведение; вычисленные количества |

Все шесть групп создаются через POST `/api/medical-records/{recordId}/prescription-chains`. UUIDv7 цепочки и редакции различаются; `prescription` содержит id, color, instruction, dates.start (UTC), опциональную dates.periodicity, specifics только для SOLUTION/MEDICATION, пустые results, creationDate. Вычисленные величины не подменяют введённую дозу и не добавляются в payload.

Сохранение использует существующий сервис: проверка актуального пациента и незаблокированного листа, GET до записи, один POST, GET после записи, сопоставление состояния с ожидаемым. Подтверждённый результат принимается общим store, откуда обновляются сетка, индивидуальная и общая ленты. Неопределённый результат POST блокирует повтор из этой формы и показывает перечитанные данные; значения формы сохраняются. Проверки сохранения используют исключительно синтетические данные и mock API.

Групповые кнопки передают тип в форму; пустые группы тоже имеют кнопки при включённом редактировании. Существующее ограничение редактирования/удаления ранее созданных цепочек (MEDICATION/NURSING) не расширялось: задача касается создания.

## Подтверждённые источники

Пользовательский HAR использован локально для пяти успешных POST (MONITORING, ACTIVITY, NURSING, PROCEDURE, MEDICATION). HAR, его ответы, идентификаторы и авторизация не включены в репозиторий.

Дополнительно прочитан публичный клиент https://app.clevervet.tech/main-WLNNV7A3.js (получен 17.11.2026). SHA256 оригинальных байтов: `9a1a74536004d325f3d5e18ce8c0efbe64267e57805fbda20b82eb5823e1d7c1`.

* `Wte`: словари шести категорий (5/7/7/12/2/2 названий соответственно).
* `OU`: словарь концентраций; MEDICATION получает объединение Wte и ключей OU, как в `_A` оригинала — всего 99 названий.
* `Eo`: регистронезависимое вхождение подстроки. `hA`: концентрации фильтруются по выбранным enum вещества и объёма, затем по вхождению введённого числа.
* `IU/Dte/sEe/kte`: сериализация общих полей, specifics, растворов и разведения.
* `Xl/pA`: «Планируемое» через наличие periodicity.
* `_A/Db/zd/wb/vU/Ib/xb/Eb`: ИПС, режимы отображения, расчёты медикамента.
* `IA/Ab/hS/gm/Ih/mS/pS/Tb/Mb`: модель растворов и компоненты скорости.

В репозитории сохранены только извлечённые статические справочники, не весь клиент. Это полный набор указанных словарей данного публичного бандла, а не универсальная база препаратов. Выбор названия не назначает дозу и не выбирает концентрацию автоматически. Предложения концентраций выбираются отдельным нажатием. Даже значения оригинального справочника требуют проверки пользователем по упаковке препарата.

## Режимы и формулы

Медикаменты:

* Полная доза = введённая доза × масса, только для KILOGRAM; для ANIMAL множитель 1.
* Количество = полная доза, приведённая к единицам вещества концентрации, / концентрация. Преобразование г↔мг↔мкг; МЕ/ммоль и прочие размерности не смешиваются с массой.
* Восстановление флакона: эффективная концентрация = количество вещества во флаконе / объём восстановления.
* ИПС — только INTRAVENOUS; включение задаёт единицы времени (по умолчанию MINUTE) и периодичность 1 час, выключение убирает время из dosage.units. Числа скорости не преобразуются в болюс.
* Итоговая жидкость = количество препарата + supplementarySolvent.volume, только для мл, с сохранением того же знаменателя времени при ИПС. Дополнительное разведение не меняет концентрацию исходного препарата.
* DOSAGE / TOTAL_SUBSTANCE / TOTAL_VOLUME подтверждены enum и switch оригинала. TOTAL_VOLUME доступен при рассчитанном количестве.

Растворы:

* Заданная скорость: specifics.scarce.value, мл/ч.
* При дегидратации: dehydration × weightKg × 8 × volumePercentage / 100 / durationHours.
* Поддержание для массы ≤20 кг: (30 × weightKg + 70) / 24, мл/ч.
* Продолжающиеся потери: ratePerWeight × weightKg, мл/ч.
* Суммарная скорость — сумма включённых компонентов; в сетке и лентах выводится сумма, а не только scarce.value. Самостоятельного поля «объём раствора» в найденном контракте нет: оно не изобреталось.

## Ограничения

* Поддержание SOLUTION при массе >20 кг отключено. В Mb оригинала обнаружена ветка `weightKg * Math.pow(30, .75)`; её клинический смысл требует дополнительного подтверждения. Заданные скорости и потери для такой массы доступны при выключенном поддержании.
* Дозирование на м² и несовместимые размерности блокируются: безопасного расчёта нет. Объёмная доза при массовой концентрации не допускается к записи. Неизвестные enum и незавершённый расчёт тоже блокируют POST.
* Восстановление поддерживается для VIAL. Другие модели приготовления, включая растворитель для концентрации на грамм, не активированы.
* Не выполнялись записи реальным пациентам и проверка production POST с реальными данными. Соответствие опирается на HAR, публичный сериализатор и mock API, а не на клиническую апробацию.
* Проверка геометрии при уменьшенной высоте окна имитирует место, занимаемое клавиатурой; это не запуск нативной клавиатуры iOS. Chromium проверен на 375/390/430 CSS px; ручная Safari-проверка остаётся ограничением.

## Проверки

`npm test`: 930 тестов, 49 файлов. `npm run build`: TypeScript, production Vite build и проверка production assets.

Новые тесты: создание шести типов в пустой категории; точный payload; час, периодичность и отсутствие specifics; локальные словари и поиск; компоненты SOLUTION и блокировка >20 кг; режимы медикаментов, несовместимые размерности, ИПС и разведение; открытие нужной формы; ACTIVITY без планирования; обновление индивидуальной и общей лент для каждого из шести типов без повторного POST. Существующие тесты покрывают ошибки API, неопределённый результат, сохранение полей, двойное нажатие, сетку, архив и изоляцию Test3.

`python tools/check_prescription_mobile.py`: Chromium, 375/390/430 px, шесть форм, пустые группы, отсутствие переполнения, прокрутка и доступность действий при высоте 430 px; по шесть mock POST на каждом размере и ровно одна новая строка для каждого сохранения. Снимки только в /tmp.
