# Stay для Test3, версия 1.2.0

Исходная версия 1.0.0 читала в оригинальном CleverVet исключительно кеш Auth0 SPA SDK с префиксом `@@auth0spajs@@`. Фильтр отбрасывает показанную запись OIDC под ключом вида `0-…`. Имена `authnResult`, `authzData` и `access_token_expires_at` соответствуют модели хранения angular-auth-oidc-client. Эти сведения объясняют сбой получения токена. Причина нулевых счётчиков событий на iPhone отдельно не установлена.

После настройки OAuth открытие оригинала создаёт в Stay одноразовую отметку с временем. Для этого скрипту не нужен доступ к содержимому кеша оригинала. При открытии Test3 скрипт ждёт существующего события App ready и выполняет Authorization Code Flow с PKCE S256 в этой же вкладке. Параметр `prompt=none` позволяет провайдеру использовать действующую SSO-сессию. Собственные state и verifier кратковременно хранятся в sessionStorage вкладки Test3. Скрипт проверяет ответ, убирает параметры callback из адресной строки и сам обменивает код на access token для API. Одноразовое событие `clevervet-mobile:test3-stay-token:v1` получает существующий обработчик Test3. После успешного GET /branches само приложение сохраняет проверенный access token до истечения срока, как и в версии 1.0.0. [Документация Auth0 по PKCE](https://auth0.com/docs/get-started/authentication-and-authorization-flow/authorization-code-flow-with-pkce)

## Что требуется от администратора CleverVet

- Разрешить Test3 как публичный браузерный OAuth-клиент для нужного API в том же tenant и на том же домене входа, где существует SSO-сессия оригинального приложения. Подойдёт существующая регистрация, если администратор явно разрешил её использование для Test3. Другой вариант — отдельный SPA-клиент. Включить Authorization Code, PKCE S256 и обмен кода без client secret.
- Зарегистрировать точный callback `https://fork995.github.io/Test3/`. Разрешить origin `https://fork995.github.io` в настройках браузерного клиента и CORS для обмена кода. Этот origin общий для проектов GitHub Pages данного владельца.
- Предоставить публичный Client ID и API Identifier (audience). Клиенту нужны разрешение на выдачу access token для этого API, необходимые claims и права на чтение филиалов. Если для входа нужны согласие или повторная аутентификация, их требуется пройти в разрешённом провайдером сценарии. Сессия самого сайта CleverVet и SSO-сессия домена Auth0 могут истекать в разное время.
- Скрипт настроен на домен авторизации из предоставленного описания, `dev-l4aq9wjx.eu.auth0.com`. Если администратор указывает другой домен SSO, требуется согласованно заменить ISSUER в скрипте и точный адрес token endpoint в CSP Test3.

## Установка и проверка на iPhone

1. Опубликуйте сборку Test3 с изменением в `app/index.html`. Политика `connect-src` должна разрешать `https://dev-l4aq9wjx.eu.auth0.com/oauth/token`. Это единственное необходимое изменение приложения. Обработчик `app/src/stayAuth.ts`, интерфейс и логика работы с пациентами используются в исходном виде.
2. В Stay замените старую копию Test3 содержимым `stay/clevervet-mobile-test3.user.js` версии 1.2.0, включая блок метаданных. Заполните константы `CLIENT_ID` и `API_AUDIENCE` согласованными публичными значениями. Пустые поля оставляют только режим 1.0.0 для прежнего кеша на www-домене.
3. В настройках расширений Safari включите Stay и разрешите доступ к используемому оригиналу (`app.clevervet.tech` или `www.app.clevervet.tech`) и к `fork995.github.io`.
4. В Safari войдите в оригинальный CleverVet, обновите его страницу и в течение трёх минут откройте Test3 в том же профиле. При действующей SSO-сессии вкладка посетит Auth0, вернётся в Test3 и откроет «Пациенты». Уже сохранённая Test3 сессия восстанавливается самим приложением. Ручной ввод, импорт из буфера и деморежим остаются доступны.
5. Для диагностики временно поставьте `DEBUG = true` в Stay и повторите шаг 4. В Safari Web Inspector включите сохранение журнала при навигации. На оригинале ожидается `authorization-request-stored`, в Test3 — `bridge-ready`, `app-ready`, `authorize`, после возврата — `token-dispatched`. `configure-oauth` или `no-legacy-token-configure-oauth` указывают на необходимость настроить клиента при новом формате кеша. `interaction-required` означает, что Auth0 требует взаимодействия. При `callback-rejected` проверьте время попытки, вкладку и callback. При `token-exchange-failed` проверьте CSP опубликованной страницы, CORS и регистрацию клиента. Статусы не содержат токенов, кодов или идентификаторов пользователей.
