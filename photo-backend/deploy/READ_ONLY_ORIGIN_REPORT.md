# Read-only проверка Origin и действующей сессии

Проверено на Orange Pi 2026-11-23. Ни одного запроса записи к реальным CleverVet API или Object Storage не выполнялось.

| Проверка | Без Origin / GitHub Pages | Origin оригинального CleverVet | Вывод |
| --- | --- | --- | --- |
| OPTIONS `/api/branches`, preflight GET + `authorization` | GitHub Pages: 200, 153 мс | 200, 67 мс | Оба ответа содержат `Access-Control-Allow-Origin: *`, `Allow-Methods: GET`, `Allow-Headers: authorization`. Прежний 403 не воспроизвёлся. |
| OPTIONS `/api/branches`, preflight POST + `authorization,content-type` | GitHub Pages: 200, 146 мс | 200, 91 мс | Это лишь preflight; реальный POST не выполнялся. |
| Настоящий GET `/api/branches` без Bearer | 401, 67 мс | 401, 69 мс | Origin не заменяет авторизацию. Тело ответа не сохранялось. |
| HEAD `https://storage.yandexcloud.net/` | 200, 102 мс, TLS проверен | Пока не применялся | Endpoint доступен. Ответ без подписи не подтверждает права на объект. |

Реальный GET с одним действительным Bearer в двух вариантах и подписанный S3 HEAD конкретного объекта требуют штатного входа администратора в Chromium и законно доступного ключа объекта. Код этих проверок развёрнут, но на момент записи браузерная сессия не была запущена. Результаты нельзя объявлять успешными до живого прогона.

Админка отвечает по HTTPS на домашнем адресе. `royaltykey-xray`, `hostapd`, `dnsmasq`, `ssh` активны; проверка маршрута клиента `192.168.50.2` к `1.1.1.1` показывает `dev rkxbox0 table 20251`. Порты 5900 и 6080 без браузерной сессии закрыты. Настройки VPN, Wi-Fi, DHCP и firewall не менялись.

Текущие ограничения: формат кэша оригинального Angular OIDC SDK может измениться; ID token может не содержать S3 credentials; без ключа существующего объекта невозможно отличить отсутствие права на bucket от права на отдельный объект; HEAD 403 не доказывает недействительность credentials. Для загрузки фото далее нужен отдельный серверный маршрут с проверкой авторизации и связи пользователя Test3 с пациентом, подтверждённой поддержкой условного обновления CleverVet API и защитой от повторной записи. До такой проверки реальные PutObject/PUT остаются отключены.
